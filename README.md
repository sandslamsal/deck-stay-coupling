# Deck-stay modal coupling and the bias of vibration-based cable force identification on cable-stayed bridges

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23005585.svg)](https://doi.org/10.5281/zenodo.23005585)

Code and data behind the results of the manuscript of the same title,
currently under review.
Authors: Sandesh Lamsal (AtkinsRéalis USA Inc.; University of Miami) and
Rubi Bhandari (EAC Consulting, Inc.; Florida International University).
Corresponding author: sandeshlamsal@miami.edu.

## Contents

- `src/cablefe.py`: the planar coupled cable-deck finite element model
  (straight stay cable, rigid pylon), the closed-form expressions, and the
  conventional tension inversions.
- `src/cablefe2d.py`: the two-dimensional model (stay cable modeled along
  its sagged profile with frame elements; optional flexible pylon), with the
  one-ended and two-ended reductions.
- `src/identify.py`, `src/shapefit.py`: the identification methods of
  Section 6.
- `src/figstyle.py`: the figure style.
- `scripts/`: one script per result, each writing a file in `data/`. The
  table below maps results to scripts.
- `data/`: the outputs the manuscript quotes, as CSV, and `record_demo.npz`
  (one simulated record). Every file in `data/` was generated by the code in
  this repository.

## Reproduction

Python 3.11 with numpy, scipy, pandas, matplotlib, joblib and openseespy.
Run every script from the repository root, for example
`python3 scripts/run_campaign.py`. Figures are written to `figures/`, or to
the folder named by the environment variable `FIGURE_DIR`. The parametric study and the operational
modal analysis take about an hour each; everything else runs in minutes.

## Third-party data

The validation in Sections 8 and 9 uses measurements published by others.
They were transcribed or digitized from the sources below for this study and
are **not redistributed** here. The analysis scripts are included; they read
the transcribed values from `data/external/`, which is not part of this
repository, and stop with a message naming the source if a file is absent.

| Source | Data | Scripts that need it |
|---|---|---|
| Kumar (2011), PhD thesis, University of Trento | Ponte del Mare footbridge: identified modes, stay frequencies, thirty-stay construction-control schedule | `validate_pontedelmare.py`, `validate_pontedelmare2.py`, `run_pontedelmare_sag.py`, `validate_traverse.py`, `falsify_traverse.py`, `bound_n4w.py`, `run_stay_census.py`, `check_intersection.py` |
| Rebelo et al. (2009) | Aveiro footbridge: stay frequencies and tensions | `validate_aveiro.py`, `check_intersection.py` |
| Caetano et al. (2000); Caetano (2001), PhD thesis, University of Porto | Jindo bridge 1:150 physical model: model properties, measured coupled and decoupled modes | `validate_jindo.py`, `jindo_window.py` |
| Ondra and Titurus (2019) | Beam-tendon rig: measured veering events | `fig_ondra.py` |

To repeat these analyses, create `data/external/<script>_data.py` holding the
named tables each script imports (the import line at the top of each script
lists them), transcribed from the source. The derived files those scripts
write into `data/` are likewise not included.
